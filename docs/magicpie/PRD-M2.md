# Magic Pie 低延迟手写与跨端闭环 PRD

版本：1.0 · 2026-09-15 · 状态：实施基线

## 1. 背景与目标

M1 已完成 Magicpie M1 自动识别、黑白高对比界面、显示与 `.bfly` 原色数据分离、ARMv7 APK、真机启动、实笔写入及保存重开。用户实笔验收结果为“可以写，但是反应很慢”，因此低延迟目标尚未完成。

M2 的目标是在不 root、不刷机、不复制或分发闭源原厂代码/二进制的前提下，先修复 Butterfly 2.5.5 已确认的实时预览缺陷，再验证并按需接入设备公开的快速手写/EPD 能力，最终完成撤销重做、导出、电脑端打开编辑及同步配置边界的验收。

## 2. 已确认事实

- 当前 `PenHandler.addPoint` 只更新 `_elementPoints[pointer]`，而前景渲染读取 `elements.values`；移动期间活动笔画未回写，完整笔画通常到抬笔后才显示。上游提交 `b04d7257484f8cd2c71ed0f9fc9072dd456a7cee` 已修复该问题。
- 恢复逐点预览后，不能对每个高频 move 无限制重建前景；上游提交 `5808263dde0de91f05286dc9333197615d081c34` 使用约 16 ms 合并刷新。
- 原厂笔记 `com.mp.evernote` 版本 2.7.0 使用 Android 系统 UID 1000 和平台签名；定制 Butterfly 使用普通 UID 10055，不能假设拥有原厂全部系统权限。
- 系统提供 `/system/lib/libhandwriting_jni.so`、`libhandwriting2_jni.so`、`libhandwriting3_jni.so`，三者列入系统 public libraries。普通应用被允许加载这些库，但初始化、设备访问及生命周期仍须真机探针验证。
- PX30 对应 Java/JNI 接口为 `com.yitoa.rk.handwriting3.HandWritingNative`。目标库可直接访问 `/dev/ebc`、Wacom 输入设备和 `disabled_report_event`；这些节点当前均为全局可读写，但不能把文件权限等同于完整功能已通过。
- 系统/API 中存在 `android.yitoa.px30.EinkRefreshUtil`，可经定制 `View` 的 `requestEpdMode`、`enterA2`、`exitA2` 等接口请求刷新模式。普通应用稳定性、模式值和恢复时序须探针验证。
- 原厂 SDK 的快速手写路径直接读取 Wacom 事件并写 EBC framebuffer，再把事件回调给应用。这与普通 Flutter Canvas 重绘是两条路径。
- 设备保存的 `.bfly` 已取回并验证：原色属性、透明度与 PNG 数据未被黑白显示适配改写，用户实笔带连续 pressure 值。

上述反编译仅用于互操作接口调查。实现只重建必要接口声明与自主生命周期代码，不复制闭源应用业务实现，不把设备系统库打包进 APK。

## 3. 功能范围

### FR-M2-01 实时 Flutter 笔迹

第二个有效采样点到达后，活动笔画必须进入前景渲染，不等到抬笔。移动事件的前景更新按帧合并，不能无限堆积异步 renderer 重建。抬笔仍只提交一个 `ElementsCreated`，保持一次撤销对应一整笔。

### FR-M2-02 厂商能力探针

使用独立 magicpie-only 探针验证普通 UID 可加载系统手写库，完成 JNI 注册、初始化、开始、停止、销毁，并验证 `EinkRefreshUtil` 的类、方法、模式请求和恢复行为。初始化失败、Activity 暂停、失焦、旋转和进程退出后不得留下幽灵笔迹、禁用普通触摸或把屏幕卡在快速模式。

探针优先使用空白合成页面。若任一调用需要平台签名、SELinux 放行或产生不可恢复状态，停止该路径并保留 Flutter 回退。

### FR-M2-03 原生快速预览

仅当探针通过时启用。原生层只承担活动笔画的即时屏显，Flutter 仍是输入数据、坐标、pressure、文件保存、撤销重做的唯一真源。原生层不得消费并阻断 Flutter 的 `MotionEvent`。

第一版快速路径限定为：Magic Pie、普通笔尖、PenTool、单指笔输入、无尺子/形状识别/临时按钮映射、画布变换在一笔期间稳定。其他情况自动回退 Flutter 预览。

原生预览与最终 Flutter renderer 必须使用同一笔画 ID 交接。最终笔画已经显示后才能清除原生层，避免双显、闪断或丢笔。

### FR-M2-04 刷新与残影

进入书写时只使用实机验证通过的快速/局部刷新模式；抬笔、暂停、离开编辑器和异常退出时恢复正常模式。定期全刷策略必须有明确触发条件，不能每点全刷，也不能无限积累残影。模式接口不可用时安全回退，不阻止保存。

### FR-M2-05 生命周期与一致性

覆盖 down/move/up/cancel、连续两笔、退后台、窗口失焦、旋转、切页、切工具、缩放平移和应用崩溃后的恢复。`ACTION_CANCEL` 不生成半截撤销项；主动切工具沿用既有 reset/submit 语义。应用重启后不能依赖原生 overlay 恢复文档。

### FR-M2-06 文件、导出与电脑端

继续使用上游 `.bfly`，不新增定制格式。完成浅纸/深纸、PNG/SVG/PDF 导出原色验证；在电脑浏览器或 Windows Butterfly 实际打开平板保存文件、编辑、保存，再由平板重开。无法运行原生 Windows 构建时，允许先用同版本 Web 构建完成文件 UI 验收，但必须记录平台边界。

### FR-M2-07 同步

保留并验证上游 WebDAV/Nextcloud 配置入口和本地文件工作流。没有用户提供的服务地址、账号和授权时，只能完成代码路径与无凭据错误处理验证，不能宣称真实云同步完成。不得把凭据写入仓库、日志或验收截图。

## 4. 非目标与安全边界

- 不 root、不刷机、不修改 SELinux、设备节点权限、system/vendor/oem 文件或平台签名。
- 不复制、提交或分发原厂 APK、反编译源码、`libhandwriting*.so`；运行时只加载设备自带的公开系统库。
- 不让原生预览成为 `.bfly` 数据来源，不更改 Butterfly 文件结构。
- 不为追求速度禁用保存、撤销、pressure、崩溃恢复或普通设备兼容。
- 不把主观“比以前快”写成原厂同等级；需要用户实笔 A/B，并尽可能记录事件到显示的时间证据。
